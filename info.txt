ПРОМПТ ДЛЯ СОЗДАНИЯ И АРХИТЕКТУРНОГО ПРОЕКТИРОВАНИЯ CRM-СИСТЕМЫ «ХОП» (V1.0)

Это подробное описание системы, предназначенное для использования в качестве мастер-инструкции (промпта) для разработки аналогичного программного продукта с нуля.

1. ОБЩЕЕ ОПИСАНИЕ СИСТЕМЫ
Система CRM HOP — это профессиональное решение для автоматизации службы хозяйственно-оперативной поддержки. Она предназначена для приема заявок от сотрудников (поломки, ремонт, IT-запросы, клининг), управления их распределением между исполнителями и контроля качества выполнения.

2. ТЕХНИЧЕСКАЯ АРХИТЕКТУРА
- Backend: Чистый PHP 8.x. Использование REST API архитектуры. Все ответы сервера в формате JSON.
- Frontend: Single Page Application (SPA) на чистом JavaScript (Vanilla JS). Использование Bootstrap 5 для стилей и Bootstrap Icons.
- Хранилище (Dual-Storage Strategy):
  - Режим 1: Файловое хранилище (JSON). Использование атомарной записи с блокировками (flock/LOCK_EX) для предотвращения повреждения данных при конкурентном доступе.
  - Режим 2: Реляционная база данных (MySQL). Использование PDO с подготовленными выражениями (Prepared Statements) для защиты от SQL-инъекций.
  - Переключение режимов осуществляется одной настройкой в `settings.json` через абстрактный класс `Storage`.

3. БЕЗОПАСНОСТЬ И АУТЕНТИФИКАЦИЯ
- Реализовать JWT (JSON Web Tokens) аутентификацию.
- Срок жизни токена — 24 часа.
- Автоматическая генерация и ротация 32-байтового HEX-секрета для подписи JWT, если он не задан в настройках.
- Хеширование паролей: Bcrypt (алгоритм PASSWORD_DEFAULT).
- Защита директорий `data/` и `includes/` через `.htaccess` (Deny from all).

4. РОЛЕВАЯ МОДЕЛЬ И ПРАВА ДОСТУПА (RBAC+)
Система поддерживает 4 базовые роли с возможностью гранулярной настройки через 30+ разрешений:
- Администратор: Полный доступ ко всем функциям и настройкам.
- Руководитель отдела: Управление заявками своего отдела, назначение исполнителей, аналитика.
- Исполнитель: Просмотр назначенных задач, смена статусов, чат.
- Пользователь (Заявитель): Создание заявок, отслеживание своих запросов, оценка качества.

Дополнительная функция: Настройка видимости вкладок меню («Задачи», «Чат», «Отдел», «Отчеты», «Админ») индивидуально для каждой учетной записи.

5. ЖИЗНЕННЫЙ ЦИКЛ ЗАЯВКИ
- Статусы: Новая (new), Назначена (assigned), В работе (in_progress), Ожидает запчастей (waiting_parts), Отложена (postponed), Нужна информация (need_info), Выполнена (completed), Закрыта (closed), Отклонена (rejected).
- Автоматизация SLA: Система должна рассчитывать дедлайн на основе типа работ (указывается в часах).
- История: Каждое изменение статуса или исполнителя логируется в таблицу `status_history` с указанием времени, автора и комментария.

6. ФУНКЦИОНАЛЬНЫЕ МОДУЛИ ИНТЕРФЕЙСА
- Dashboard: Сводная информация и быстрые фильтры.
- Табличный вид: Сортируемые списки заявок с постраничной навигацией.
- Kanban-доска: Перетаскивание карточек (SortableJS) между колонками статусов. На экранах >1400px отображать 4 колонки в ряд.
- Чат: Общий чат для сотрудников и контекстные комментарии внутри каждой заявки.
- Конструктор форм: Возможность добавлять кастомные поля к заявкам через админку.
- Файловый менеджер: Загрузка изображений и документов (валидация расширений и размера до 5МБ).

7. МОБИЛЬНАЯ ВЕРСИЯ (MOBILE FIRST)
- Отдельный интерфейс в директории `/mobile/`.
- Имитация нативного приложения: Bottom Nav Bar, отсутствие скролла на `body`, использование `backdrop-filter: blur`.
- Поддержка PWA: Файлы `manifest.json` и `sw.js` (Service Worker) для установки на Android/iOS.

8. АНАЛИТИКА И ОТЧЕТНОСТЬ
- Визуализация через Chart.js (распределение по статусам, приоритетам, нагрузка на отделы).
- Экспорт данных в CSV с поддержкой UTF-8 BOM для корректного открытия в Excel.
- Детализированная история активности каждого исполнителя (Executor Drill-down).

9. АДМИНИСТРАТИВНЫЕ ИНСТРУМЕНТЫ
- Backup System: Создание ZIP-архива всей папки `data/` и настроек одной кнопкой.
- Demo Seeding: Функция мгновенного наполнения базы 500+ случайными заявками для демонстрации возможностей.
- Журнал входов: Логирование IP-адресов и времени входа всех пользователей.

10. UX ТРЕБОВАНИЕ: АВТО-ФИЛЬТРАЦИЯ
- Любое изменение в полях фильтров (текстовый поиск, выбор статуса, приоритета или даты) должно немедленно и автоматически обновлять список данных без необходимости нажатия кнопки «Найти».
