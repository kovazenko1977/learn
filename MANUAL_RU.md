# Руководство пользователя: Helpdesk Enterprise v6.0 🧩
**Разработчик:** Kovazenko S.B.

**Helpdesk Enterprise** — это профессиональная автономная система управления заявками, интегрированная в WordPress, но работающая на собственной независимой архитектуре. Система предназначена для обеспечения прозрачности, дисциплины и автоматизации бизнес-процессов в средних и крупных компаниях.

---

## 1. Начало работы

### 1.1. Установка
1. Загрузите плагин в папку `/wp-content/plugins/`.
2. Активируйте его через админ-панель WordPress.
3. При активации система автоматически создаст необходимые таблицы в базе данных и пользователя по умолчанию:
   - **Логин**: `admin`
   - **Пароль**: `admin`
   *Обязательно смените пароль после первого входа!*

### 1.2. Создание страниц доступа
Для того чтобы пользователи могли работать с системой на сайте, создайте страницу (например, "Поддержка") и добавьте на нее основной шорткод:
`[hd_dashboard]`

---

## 2. Настройка системы (Админ-панель)

Перейдите в меню WordPress: **"Поддержка"**.

### 2.1. Отделы (Departments)
Здесь вы создаете структуру компании. Для каждого отдела можно настроить:
- **Руководитель**: Выбирается из списка пользователей системы.
- **График работы**: Время начала и конца рабочего дня (например, 09:00 - 18:00).
- **Обед**: Перерыв, который будет вычитаться из расчета SLA.
- **Выходные и Праздники**: Конкретные дни, когда поддержка не оказывается.

### 2.2. Категории (Categories)
Категории определяют тип проблемы и правила её решения:
- **SLA (часов)**: Базовое время на выполнение заявки.
- **Приоритет**: Низкий (x1.5 времени), Средний (x1.0), Высокий (x0.5) или Критический (x0.25).
- **Исполнитель по умолчанию**: Кто автоматически получит заявку при её создании в этой категории.

### 2.3. Пользователи (Users)
Система использует **автономную базу пользователей**, независимую от стандартных пользователей WordPress. При регистрации используется **номер телефона** вместо email.
- **Роли**:
  - `Администратор`: Полный доступ ко всем данным и настройкам.
  - `Руководитель отдела`: Видит и управляет всеми заявками своего отдела.
  - `Исполнитель`: Работает только с назначенными ему заявками.
  - `Ответственный`: Создает заявки и следит за их выполнением.

## 3. Работа с заявками (Shortcodes)

Вы можете использовать следующие шорткоды для гибкой настройки личных кабинетов:

| Шорткод | Описание | Кому полезно |
| :--- | :--- | :--- |
| `[hd_dashboard]` | Полноценный интерфейс: Статистика + Список + Форма. | Всем ролям |
| `[hd_request_form]` | Только форма создания новой заявки с загрузкой фото. | Ответственным сотрудникам |
| `[hd_request_list]` | Список заявок с фильтрами и кнопками просмотра. | Исполнителям и Ответственным |
| `[hd_admin_settings]` | Форма глобальных настроек (Telegram, SLA и т.д.). | Только Администраторам |
| `[hd_admin_departments]` | Интерфейс управления отделами и графиками. | Только Администраторам |
| `[hd_admin_categories]` | Управление категориями и множителями SLA. | Только Администраторам |
| `[hd_admin_users]` | Полный список и управление персоналом (по номеру тел.). | Только Администраторам |

> **Примечание:** Если к шорткодам администратора обращается обычный пользователь, система покажет форму входа для авторизации под учетной записью Администратора.

## 4. Система уведомлений Telegram

### 4.1. Настройка бота
1. Создайте бота через `@BotFather` в Telegram.
2. Вставьте полученный Токен в настройки плагина (**Поддержка -> Настройки**).
3. Укажите `ID чата администратора` для получения системных алертов.

### 4.2. Для пользователей
Чтобы получать личные уведомления, пользователь должен:
1. Зайти в свой профиль через `[hd_dashboard]`.
2. Указать свой **Telegram Chat ID** (его можно узнать у `@userinfobot`).
Система будет уведомлять о: новых заявках, смене статуса, комментариях и просрочках.

## 5. Модель SLA (Service Level Agreement)

SLA рассчитывается автоматически в момент создания заявки.
**Формула:** `Базовый срок категории` × `Множитель приоритета`.

**Умный расчет:**
- Если заявка создана в 17:30, а рабочий день до 18:00, остаток времени перенесется на следующее утро.
- Выходные, праздники и обеденные перерывы полностью игнорируются при отсчете времени.
- В карточке заявки всегда видна актуальная информация: "Просрочено на..." или "Осталось времени...".

## 6. Для разработчиков (REST API)

Система готова к интеграции с мобильным приложением Android.

**Базовый URL:** `https://ваш-сайт.рф/wp-json/hd/v1/`
**Авторизация:** Заголовок `X-HD-Token: <ваш_api_token>` (токен можно найти в личном кабинете).

**Основные методы:**
- `POST /login` — Авторизация (логин/пароль).
- `GET /requests` — Список доступных заявок.
- `GET /requests/{id}` — Детали заявки, история и фото.
- `POST /requests` — Создание новой заявки.
- `POST /comments` — Добавление комментария.
- `POST /status` — Изменение статуса (для исполнителей).

## 7. Безопасность и Прозрачность

1. **Immutable Log**: Каждое действие (смена статуса, удаление фото, назначение исполнителя) записывается в историю. Удалить запись из истории невозможно.
2. **Контроль данных**: Только Администратор имеет право окончательно удалять заявки или комментарии.
3. **Изоляция**: Пользователи видят только то, что им положено по роли. Исполнитель не увидит заявки чужого отдела.
