ПОЛНЫЙ ТЕХНИЧЕСКИЙ ПРОМТ ДЛЯ РАЗРАБОТКИ ВЕБ-ПРИЛОЖЕНИЯ «ХОП» (Хозяйственно-Оперативные Поручения)

1. КОНЦЕПЦИЯ И ЦЕЛЬ
Разработать автономное веб-приложение для управления хозяйственными и техническими заявками в медицинском учреждении. Система должна заменить бумажный и устный документооборот, обеспечивая прозрачность, контроль сроков (SLA) и мобильность сотрудников.

2. АРХИТЕКТУРНЫЕ ТРЕБОВАНИЯ
- Backend: PHP 8.3+ (без использования фреймворков для максимальной легкости и автономности).
- База данных: NoSQL подход на основе JSON-файлов в директории /data/.
- Безопасность данных: Использование механизма flock() для предотвращения конфликтов при одновременной записи. Защита директории данных через .htaccess.
- Структура: PSR-4 автозагрузка классов, разделение логики (Менеджеры) и представления (Шаблоны).
- Frontend: Чистый HTML5, CSS3 (современные переменные, Flexbox, Grid) и Vanilla JS. Использование иконок Lucide.

3. ВИЗУАЛЬНЫЙ СТИЛЬ (Windows 11 "Mica")
- Цветовая схема: Светлые тона, чистый белый и светло-серый (#f9f9f9) фон.
- Эффекты: Эффект матового стекла (backdrop-filter: blur), закругленные углы (radius: 10px), тонкие границы (1px solid rgba(0,0,0,0.06)).
- Шрифты: Использование Inter или Segoe UI Variable.
- Анимации: Плавные переходы (0.3s cubic-bezier), анимации появления (slideUp, fadeIn) для всех элементов интерфейса.

4. МОБИЛЬНАЯ ОПТИМИЗАЦИЯ (Mobile-First)
- Навигация: Фиксированная нижняя панель («плавающая» на мобильных) с основными разделами: Задачи, Чат, Создать (+), Инфо, Профиль.
- Интерфейс: Крупные сенсорные элементы, отсутствие горизонтальной прокрутки, адаптивные таблицы (карточки на мобильных).
- PWA: Полная поддержка манифеста и Service Worker для установки как приложение на главный экран. Наличие приглашения к установке для мобильных пользователей.

5. РОЛЕВАЯ МОДЕЛЬ (RBAC)
- Инициатор: Создание заявок, подтверждение выполнения, оценка качества.
- Исполнитель: Принятие в работу, отчет о выполнении (текст + фото).
- Ответственный службы: Распределение заявок внутри своей службы.
- Контролер: Проверка качества выполненных работ.
- Руководитель: Просмотр аналитики, отчетов и KPI.
- Администратор: Полное управление системой, справочниками и настройками.

6. КЛЮЧЕВОЙ ФУНКЦИОНАЛ
6.1. Жизненный цикл заявки:
Новая -> Назначена -> В работе -> Проверка -> (Доработка) -> Выполнена -> Закрыта.
6.2. Уведомления:
- Внутренняя система уведомлений с badges и звуковым сигналом.
- Интеграция с Telegram Bot (персональные и групповые уведомления по Chat ID).
- Кликабельность: нажатие на уведомление ведет на страницу соответствующей заявки.
6.3. Коммуникации:
- Общий чат для объявлений.
- Кнопки быстрого вызова (tel:) для связи между инициатором и исполнителем прямо из карточки заявки.
6.4. Аналитика:
- Дашборд с показателями нагрузки, просрочек и эффективности.
- Лидерборд лучших сотрудников на основе рейтинга и количества выполненных задач.
6.5. Администрирование:
- Управление персоналом: обязательное поле «Телефон», фильтрация по ролям.
- Управление объектами: многоуровневые локации (Корпус -> Этаж -> Кабинет).
- Управление SLA: настройка времени выполнения для каждого приоритета (Низкий, Средний, Высокий, Критический).
6.6. Обслуживание:
- Инструменты резервного копирования в ZIP.
- Селективная очистка данных (Архивация) по дате и типу данных (Заявки, Чат, Уведомления).
- Генератор демо-данных для тестирования (>100 записей).

7. ТРЕБОВАНИЯ К КОДУ
- Чистый, документированный код на русском/английском.
- Отсутствие внешних тяжелых зависимостей (только легкие CDN для иконок и шрифтов).
- Обработка ошибок и валидация форм (CSRF защита обязательна).
